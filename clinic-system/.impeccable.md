# Design Context — 口腔诊所管理系统

## Target audience
前台接待、口腔医生、收费员、诊所负责人（四类内部角色，见表5 / 系统用例图）。
工作场景：前台高并发登记与冲突处理、医生快速查看当日安排、收费员核对金额与欠款、
负责人查看统计与提醒。桌面为主，窄屏（手机）需保留关键操作。

## Use cases
UC-01 登记患者并预约诊疗（含身份待核对与时段冲突分支）
UC-02 录入收费并处理欠款
UC-03 录入义齿订单并追踪交付
UC-04 查询统计与订单提醒
配套：基础信息维护、录入诊疗。

## Brand personality / tone
**临床编辑风（Clinical Editorial）**：冷静、精确、可信赖，带编辑式排版的克制温度。
不是"蓝白渐变 SaaS 模板"，而是有纸感底色、深墨绿主色、单一朱红强调色的专业医疗工作台。
记忆点：左侧深墨绿导航像病历脊背，工作区像一张干净的诊疗记录纸；数字用等宽表格数字，
状态用细线胶囊标签；登录页用真实诊所照片建立场景感。

## Constraints
- 原生 HTML/CSS/JS，无构建工具；GitHub Pages 静态托管。
- 功能契约零改动：所有 DOM id / class、表单字段、API 路径、模块逻辑保持不变。
- 强制服务器模式，登录必须先连接 API。
- 可访问性：正文对比度 ≥ 4.5:1，焦点可见，触摸目标 ≥ 44px，尊重 prefers-reduced-motion。
- 中文字体不依赖单一 CDN：字体加载失败时降级到系统宋体/黑体仍成立。
